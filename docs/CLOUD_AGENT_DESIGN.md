# CabinPilot 云端与台架 Agent 设计（定案）

> 状态：设计已确认（2026-11-07），实现按第 12 章分步进行。4.7 节和第 14 章是已定方案，尚未实现。当前代码的实际情况见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 原则

**要碰车机的放本地，其余都放云端。**

- 只有一条主线，不区分白天和夜间模式。
- 云端管"测什么"和"结果怎么算"，台架 Agent 管"怎么跑"。
- 回放不调模型，判定只走云端，保证结果可复现、标准一致。

## 2. 主流程

```
云端 Web：PRD / 对话 → 需求点 → 用例 → AI 自检 → 人工审核入库 → 生成 YAML → 静态校验
    ↓
台架 Agent：首次试跑 → 回传定位与结果 → 云端固化，用例状态变为"已验证"
    ↓
台架认领用例（车型 + OTA + PRD 版本）→ 定时或手动触发 → 任务池
    ↓
台架 Agent 领取并执行
    ├─ 通过：只上报摘要
    └─ 失败：上传日志与视频到云端（断网时补传）
    ↓
回归任务自动跨台架复测，未复现记"不稳定"，不送审
    ↓
云端查重、合并 → 待审核（按车型 / 模块 / OTA / 个人展示）
    ↓
审核人确认 → 云端建 Jira 并上传附件 → 清理云端证据
```

## 3. 职责边界

| 能力 | 位置 |
|---|---|
| PRD 导入、用例生成、用例审核入库、YAML 生成 | 云端 Web（含对话框） |
| 用例库、测试代码、车型字典、模块配置 | 云端 |
| 台架管理、用例认领记录、任务池、定时触发 | 云端 |
| 缺陷审核、查重、建 Jira | 云端 |
| 结果统计、看板 | 云端 |
| 模型密钥与判定 | 云端 |
| 回放执行、日志与录屏采集、离线补传 | 台架 Agent |
| 实时投屏、本机状态、现场下发测试、选 PRD 版本并认领用例 | 台架 Agent 本地页面 |

本地对话框只管执行。说"生成用例"时提示并给出云端链接。对话工具按场景分开：云端只开放用例相关工具，本地只开放执行相关工具。

本地页面只监听 127.0.0.1，并校验 Host 与 Origin。

## 4. 台架

### 4.1 车型

本地页面下拉选择车型，选项来自云端车型字典：B01欧版、A01国内、A01国际、D01、E01。

- 只能在空闲时切换，切换后重新注册。
- 能读到车机车型且与手选不一致时，本地和看板告警。
- 每条执行结果记录当时的车型。

### 4.2 硬件能力

| 硬件 | 能力标签 |
|---|---|
| 喇叭 + 麦克风 | `audio` |
| CAN 工具 | `can` |
| 摄像头 | `camera` |
| ADB 连接 | `adb` |

一期在本地页面勾选声明；外设自动检测放二期。

### 4.3 用例集与任务匹配

台架当前 OTA 下已认领的用例，就是这台台架的回归范围。云端的固定用例集保留，作为快速认领的模板，按车型和模块选择，保存时校验车型和硬件能力。

- 只有"已验证"的用例能进用例集。
- 临时更换用例只影响当次，不改固定配置。
- 触发方式：云端定时，或随时手动（本地页面"立即运行本台架用例"）。
- 测试代码随任务下发，版本由云端锁定，一轮内版本一致。
- 派发条件：车型一致 + 能力覆盖，由云端干跑校验判断。没有台架能跑的进"缺台架能力"清单。
- 硬件声明只决定派发。真实音频、CAN、摄像头通道接入前，声明了也跑不了，执行时以"台架缺少能力"阻塞。
- 用例由台架认领，规则见 4.7 节。任务下发后本地不再挑选，只能看到本机可领取的任务。

长任务优先、互斥规则、掉线转移放二期。

### 4.5 定时与回归批次

- 每台台架可设每天一个时间，在看板配置。同一时刻到点的台架合成一轮回归，手动"立即运行"单独一轮。
- 定时任务没有发现人。
- 保存时今天已过点的，从明天开始。云端在到点时重启过，1 小时内补跑，再晚等第二天，避免白天突然开跑。
- 定时任务跑这台台架当前 OTA 下已认领的用例。
- 到点时台架离线或当前 OTA 没有认领用例，记在批次的"未执行"里，不重试，每日汇总能看到。

### 4.6 跨台架复测

只有回归批次复测，现场下发的任务失败后直接送审。

- 优先换一台同车型、同 OTA、能跑这条用例的在线台架；没有其他台架时，在原台架再跑一次。
- 同指纹的问题已经在待审核，或同版本已有审核结论时，不再复测。

| 复测结果 | 处理 |
|---|---|
| 失败且指纹相同 | 复现，送审，两台台架合并成一条，证据留一份 |
| 通过 | 记"不稳定"，不送审，删除证据 |
| 失败但指纹不同 | 原问题记"不稳定"，新问题送审 |
| 没有可用台架、离线、超时、撤销 | 没有结论，照常送审，注明"未能复测" |

### 4.4 首次试跑

测试代码通过静态校验后，自动派到一台在线、能跑的台架，优先空闲的。没有台架时待试跑，可在用例工作台手动发起。

| 结果 | 用例状态 |
|---|---|
| 通过 | 已验证，可以认领 |
| 断言失败、定位失败、测试代码校验失败 | 试跑未通过，写明原因，不进缺陷审核 |
| 台架断连、超时、缺能力、撤销 | 退回已生成，可以再试 |

- 没有人工跳过试跑的入口。
- 试跑不计入质量统计。
- 测试代码重新生成后要重新试跑，已认领但未验证的用例派发时跳过。
- 试跑期间测试代码又生成了新版本，这次结果作废。

一期试跑只用来判定，不把定位和耗时写回测试代码（A-12 的回写未实现）。

### 4.7 用例认领（待实现）

台架经常来回刷 OTA，用例又依赖模块的 PRD 版本，所以回归范围由台架按当前环境认领，云端保证不重复。

选择顺序：

```
选车型 → 自动读 OTA（只读）→ 选模块 → 选 PRD 版本 → 选用例 → 认领
```

- 车型选过后记住，下次启动不用重选。
- OTA 读不到时不能认领。
- 用例默认只显示未认领且这台能跑的，可以切换查看已认领、已完成。
- 按区间选时，序号按当前筛选后的列表计算，不按用例 ID 计算，因为编号不一定连续。也可以逐条勾选。
- 本地只显示轻量表格（用例 ID、标题、模块、状态、认领人），详情链接到云端。云端显示完整的认领情况，可以释放。

认领规则：

- 唯一键是 车型 + OTA + 用例 ID，同车型、同 OTA 只认领一次。PRD 版本不进唯一键，只作为记录，否则同一 OTA 可能被两台按不同版本重复跑。
- 云端原子判断。两台同时认领时只有一台成功，并返回哪些用例没抢到。
- 状态分已认领、执行中、已完成。通过、失败、不稳定算已完成；阻塞和取消退回已认领。
- 已完成的用例要重跑时，重新认领。

PRD 版本先由台架手选，不维护 OTA 与 PRD 版本的对应表：

- 下拉框只列已发布的基线，显示 PRD 名称和版本。基线按 PRD 建，一个模块可能有多份 PRD。
- 同车型、同 OTA 已有台架认领过时，默认用同一版本；否则默认用最新已发布版本。
- 改成别的版本时弹出提示，并在 Web 上标记。
- 执行结果和 Jira 单都带上 PRD 版本和用例修订，用来区分真问题和选错版本。

执行时按基线锁定：

- 认领时记下基线和用例修订，派发取这个修订，不取当前修订。
- 认领不锁测试代码版本。开始执行时才下发，取这个修订已验证的版本。
- 修订未验证的不能认领，列表写明原因。
- 开始执行前再读一次 OTA，和认领时不一致就不执行。

释放：

- 台架 OTA 变化时，未完成的认领自动释放，同 OTA 的其他台架可以接手；已完成的记录保留。
- 切换车型前提示，确认后释放未完成的认领。
- 台架离线超过 24 小时（暂定，可配置）时释放未完成的认领，Web 上也可以手动释放。

不受认领限制的情况：跨台架复测、首次试跑、现场下发。复测沿用被复测执行单元的用例修订。

## 5. 模型配置

| 用途 | 使用的模型 | 本地能否修改 |
|---|---|---|
| 回放执行 | 不调模型 | 不能 |
| 判定（视觉、语音） | 云端配置 | 不能 |
| 用例生成、云端对话 | 云端配置 | 不能 |
| 本地对话、AI 探索 | 默认跟随云端，可本地自配 | 云端授权后可以，默认关闭 |

云端设置页配置接口类型（Anthropic 或 OpenAI 兼容）、地址、对话模型、视觉模型和 Token，只有管理员能改，保存后立即生效。没配时用环境变量。

- 测试连接会各发一次对话和看图，模型名或视觉能力配错时能当场发现。
- Token 加密存储，页面只显示后 4 位。换地址必须重新填 Token，旧 Token 不会发给新地址。
- 语音合成固定走 MiniMax，不受这里影响。

本地配置页未做：AI 探索还没迁到台架，本地对话也走云端，目前没有用到本地模型的地方。

## 6. 证据

| 证据 | 规格 | 来源 |
|---|---|---|
| 日志 | 最近 3 分钟 | 台架固定目录下的 tar.zip，`adb pull` 获取，路径可配置（待提供） |
| 视频 | 1 分钟：失败前 55 秒 + 后 5 秒，可配置 | ADB 录屏分段循环，失败时用 ffmpeg 拼接 |
| 录音 | 需要时 | `adb screenrecord` 不录声音，用测试麦克风录音合成 |

录屏用 `screenrecord` 每段 15 秒写到车机、循环 3 分钟，失败时拉回来用内置的 ffmpeg 拼接裁剪，车机上不留文件。码率 1.5 Mbps，真机实测 1 分钟约 8 MB。录屏不可用时退回每秒截图合成。视频和日志在收尾动作之前保住。循环缓冲留够 3 分钟，再按 `fail_at` 截取，因为视觉判定有延迟。

- 通过的用例和未复现的失败不传证据，只上报摘要。
- 失败证据临时存云端磁盘目录，有容量上限；建票或驳回后删除，未处理 7 天后过期。
- 过程截图只在本地页面查看；只有失败的回放才上传证据，试跑和通过的不上传。本地证据保留 7 天或 20 GB。
- 日志原样上传，VIN 和手机号由应用开发时打码，这里不再处理。
- 版本号只用整车 OTA 版本。

## 6.1 确定性断言

预期里的数值能从系统读到时，用 `read_value` 读出存为事实，再由 `value` 断言比较。读值来源只允许 `settings:<system|secure|global>/<键>` 和 `getprop:<属性>`。视觉判定分不出 255 和 250，失败时规则为 J-09，高置信。

前置条件由 `apps/cloud/preconditions.yaml` 按车型翻译成命令，命令必须符合 `SHELL_PATTERNS`，云端生成和台架装载时各校验一次。匹配不到的小句不设置，结论降为低置信。

## 7. 查重

查重字段：车型、OTA 版本、用例号、断言 ID、失败类型。

指纹由车型、用例号、断言 ID、失败类型组成，OTA 版本在查重时比较，这样才分得出老问题延续。多台台架报同一问题时，并成一条待审核，记录所有台架。

| 情况 | 处理 |
|---|---|
| 全部相同 | 不建新票，提示已存在 |
| 版本不同、其他相同 | 提示"老问题延续"，由人选择追加证据或新建 |
| 上个版本通过、这个版本失败 | 新建，标记"回归" |

查重要直接查 Jira，只查云端会漏掉人工建的票。建票时写入指纹标签，下次按标签搜索。驳回过的问题由审核记忆过滤。

## 8. 审核与角色

| 字段 | 含义 |
|---|---|
| 发现人 | 跑测试的人，取触发任务的账号或台架当前登录的同事；KPI 算在这里 |
| 审核人 | 实际提交审核的账号 |

- 模块配置成员名单，一个模块可以有多人。
- 待审核默认归发现人；定时任务没有发现人时，归模块全部成员。
- 第一个提交审核的人生效，其他人再提交时提示已被谁处理。
- 登录后默认显示"我的待审核"，可切到全局视图，全局视图所有人可见。
- 展示维度：车型 → 模块 → OTA 版本，可按人筛选。
- KPI 只统计审核确认的 Bug，同时展示驳回率。

## 9. Jira

Jira 地址、公共服务账号、车型到项目的映射，都只在**云端 Web 配置页**填写，管理员可改，所有台架共用。Agent 不接触 Jira 账号。

### 9.1 账号映射

飞书登录和 Jira 账号是两套账号，用"服务账号 + 映射用户名"关联，同事不填密码：

1. 同事用飞书登录云端。
2. 云端按飞书邮箱查 Jira 用户并自动关联，两边邮箱一致。
3. 查不到时，同事在"个人设置"里填一次 Jira 用户名。
4. 建票时用服务账号调用 Jira，报告人设为发现人。

服务账号需要"修改报告人"权限，暂定可以。拿不到时退回个人 Token：Jira 支持生成 Token，同事在"个人设置"填一次，云端加密保存，只用于建票。没填的用服务账号建票，并在描述中写明发现人。

无论哪种方式，KPI 都按云端记录的发现人统计。

凭证用 `CABIN_SECRET_KEY` 加密，管理员由 `CABIN_ADMINS` 指定。个人 Token 兜底尚未实现。

### 9.2 建票

- 按车型映射到 Jira 项目、模块和版本字段。同一问题出现在多个车型上时分别建票并互相关联。
- 工单内容：现象、期望与实际、复现步骤、时间点、车型、OTA 版本、台架、复现情况、发现人、审核人。
- 建票失败进重试队列，用幂等键防止重复建单。
- Bug 状态由云端用服务账号同步，用于统计已关闭和未关闭的数量。

### 9.3 附件上限 30 MB（暂定）

先压缩视频，日志包不截断。仍超限时不传视频，在工单里写明情况，不因附件过大而建票失败。

## 10. 结果统计

层级：OTA 版本 → 回归批次 → 车型 → 台架 → 执行单元。

结论、耗时、OTA 版本、车型、模块、台架、用例修订、发现人都拆成数据库字段，用于统计。

| 指标 | 口径 |
|---|---|
| 用例覆盖率 | 已执行 ÷ 该车型该基线应执行 |
| 需求覆盖率 | 至少有一条用例跑过的需求点 ÷ 全部需求点 |
| 通过率 | 阻塞不算失败，单独统计 |
| 不稳定 | 复测未复现的，单独统计，不算缺陷 |
| Bug | 按新问题、回归、老问题延续、同版本重复分类 |

看板分 6 页，一期做 1、2、4，已实现。台架页和待审核页单独成页，人员 KPI 放在总览：

1. 总览：回归进度、在线台架、待审核数量。
2. 批次详情：按车型和台架展开。
3. 版本质量：两个版本对比。
4. 覆盖矩阵：用例 × 车型。
5. 台架健康：在线率、阻塞率、不稳定率。
6. 缺陷统计：按严重度、分类、模块、人看趋势。

## 11. 无人值守的保障

- 冒烟用例失败率超过 20% 时暂停本车型。
- 车机失联时自动重连一次，磁盘不足时停止领取。
- 任务和待审核候选持久化，云端重启不丢：启动时接回没跑完的执行单元，台架照常回传。断网超过宽限期后补传的结果也照常进入复测和审核。
- 每天 08:30 飞书推送汇总，附审核链接，范围从上次推送算起；回归批次不再逐条通知。时间由 `CABIN_DIGEST_AT` 配置，定时和汇总按 `CABIN_TZ_HOURS`（默认东八区）计算。
- 前置条件按车型维护命令白名单，由 Agent 自动设置。

## 12. 实施顺序

已完成：第 1~8 步。第 9~11 步待实现。

1. 用例和对话迁到云端。
2. 模块成员、车型选择、硬件声明、台架用例集、按车型和能力派发。
3. 结果摘要、确定性断言、前置条件白名单。
4. 首次试跑，通过后才算"已验证"。
5. 失败证据、日志和录屏采集、临时存储。
6. 云端查重、审核、多维度展示、Jira 建票。
7. 任务持久化、定时触发、跨台架复测、合并、飞书汇总。
8. 模型配置、完整看板。
9. 云端用例认领：认领表、接口、修订号贯穿派发和执行、定时回归改用认领、Web 认领视图。
10. Agent 本地认领页：选择流程、用例表格、OTA 变化处理。
11. Agent 打包与自升级，见第 14 章。
